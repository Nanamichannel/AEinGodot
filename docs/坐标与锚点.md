# 坐标、锚点与层级：踩过的坑

> 换上下文时先读这份。下面每一条都是实际调试出来的，不是推测。
> 涉及文件：`ae/export-motion-engine.jsx`、`addons/ae_motion/ae_builder.gd`。

---

## 0. 一句话规则

**节点原点 = AE 锚点；`position` 直接用 AE 的值；子层坐标要减掉父级的锚点。**
违反其中任何一条，就会出现“位置对、旋转错”或“看着差不多、一动就偏”的问题。

---

## 1. 单位与坐标系

| 项 | AE | Godot 2D | 换算 |
|---|---|---|---|
| 单位 | 像素 | 像素 | 1:1 |
| 时间 | 秒 | 秒 | json 里是毫秒，播放时 `/1000` |
| 原点 | 合成左上角 | 画布左上角 | 相同 |
| Y 方向 | 向下 | 向下 | **相同，不要取反** |
| Z 方向 | +Z 远离相机 | -Z 远离相机 | 3D 里 `godot_z = -ae_z` |

> 2D 部分**没有任何轴翻转**。曾经因为“AE 的 Y 向上”这个错误印象把 y 取反过一次，结果整体上下颠倒。

---

## 2. 锚点（anchor）

### 2.1 节点原点必须落在锚点上

```gdscript
sp.centered = false
sp.offset = -(Vector2(anchor.x, anchor.y) - (Vector2(asset_w, asset_h) - tex_size))
# tex_size == asset_size 时即 offset = -anchor
```

这样绘制矩形是 `[-anchor, size-anchor]`，**节点原点正好在锚点**，`rotation` / `scale` 都绕锚点，和 AE 一致。

### 2.2 ❌ 不要这样做（踩过的坑）

```gdscript
# 错误写法：把原点挪到图层左上角
sp.position = ae_position - anchor
sp.offset = Vector2(asset_w, asset_h) - tex_size
```

绘制位置看起来是对的，但：

- **旋转轴心跑到了左上角**（`左右护法` 的锚点在正中心，结果它绕左上角甩）
- **缩放轴心也错了**，位置偏差 = `anchor × (1 - scale)`（例：anchor 386.5、scale 0.96 → 偏 15.46px）

这个坑当时是为了修“子层相对父级原点”而引入的，代价比收益大，已回退。

## 3. 父子层级

### 3.1 AE 的子层坐标相对**父级的图层原点**，不是父级锚点

```
子层在合成里的位置 = 父级.position - 父级.anchor + 子层.position
```

例（`设置.json`）：

```
空9       position (960, 540)   anchor (0, 180)
登入成功   position (-14, -418)
→ 合成 (960-0, 540-180) + (-14,-418) = (946, -58)   ← 画面外上方
```

如果按“相对父级锚点”算会得到 `(946, 122)`（画面内），差 180px —— 这就是“位置严重偏下”的根因。

### 3.2 必须保留真实层级，不要 flatten

flatten（把世界坐标摊平、所有层平铺）会丢掉：

- 父级的 `scale`（`合成 1` 里 null 是 1.03，漏乘 → y 偏 40px）
- 父级的 `rotation`
- 父级动画（父级动，子层不跟）

当前实现：2D 层的父级如果也是 2D 层，**真正挂进去**，子层坐标用 `position - 父级.anchor`。

### 3.3 创建顺序

子层可能先于父层被创建（按 z 排序时）。必须先递归创建父节点：

```gdscript
if pid > 0:
    _node_for(pid)          # 先确保父级存在
    parent = _nodes[pid]
```

否则子层找不到父级，会被挂到根上，然后位置错乱。

## 4. 2D 层在 3D 合成里的两套空间

有相机的合成会生成这样的结构：

```
合成 (Node2D)
├─ 2D后层 (CanvasLayer, layer=1)   ← 靠后的 2D 层
├─ 3D画面 (CanvasLayer, layer=2)
│  └─ 3D容器 (SubViewportContainer)
│     └─ 3D视口 (SubViewport) → 3D世界 (Node3D) → Camera3D + Sprite3D
└─ 2D层 (CanvasLayer, layer=3)     ← 靠前的 2D 层
```

要点：

1. **3D 必须走 SubViewport**。直接把 `Node3D` 放在场景里，会被 2D 画布永远盖住（Godot 先画 3D 再画 2D）。
2. **`z_index` 只在同一个 CanvasLayer 内排序**；跨层按 `layer` 号。所以 2D 层要盖住 3D 内容，只能靠 `layer` 号。
3. **2D 层没有经过相机投影**：3D 内容在 z≈-12 处被 fov 缩放 0.9486，2D 层是 1:1。静态相机时误差 <5%，可忽略；相机一旦推拉，2D 层就会和 3D 内容脱开。

## 5. 3D 层

```
godot_pos = Vector3(ae_x - w/2, -(ae_y - h/2), -ae_z)     # 根级
godot_pos = Vector3(ae_x, -ae_y, -ae_z)                  # 子级
godot_rot = Vector3(-rx, -ry, -rz)                       # 三轴都取反
fov       = 2 * atan((h/2) / zoom)                       # zoom 是像素焦距
```

已验证：四个角标记点渲染误差 ≤1px（半像素取整）。

`Sprite3D` 另有两个坑：

- `offset = (-anchor.x, -anchor.y)`（**纵向是负**，因为 3D 的 Y 向上）
- 同深度的透明精灵靠 `render_priority = 100 - z` 决定前后，否则叠放顺序随机

---

## 6. 分段与关键帧

1. **分段按帧填**，不是秒。`intro:0-24; idle:24-240*`
2. **末帧必须包含**：区间比较用毫秒整数，不要用浮点秒。曾经因为 `259 帧 = 4.3167s` 而采样值是 `4.317s`，最后一帧被切掉，动画少 1 帧。
3. **静态值要和轨道同源**：某通道在整段里动过、但在这段里是常量时，也要建一条单帧轨道。否则切段后它会停在上一段的姿态。
4. **循环段首末必须一致**：不一致就是每圈跳一次，导入器会警告并指出哪个层差多少。
5. **`animation_finished` 里不能直接 `play()`**，要 `await get_tree().process_frame` 再切。

---

## 7. 其它容易误判的点

| 现象 | 其实不是坐标问题 |
|---|---|
| 某层“消失”了 | 先查这一段的不透明度轨道；AE 里它可能本来就是 alpha 0 |
| 某层“被挡住” | 先查 `z` 顺序和 CanvasLayer 的 layer 号 |
| 循环时整块面板跳 | 循环段首末不一致（查日志里的 ⚠） |
| 导入了两份、一份是旧的 | 合并模式以前只加不换；现在同名会替换 |
| 动画一进场景就播 | 生成时默认自动播；要手动控制就删 `AutoSequence` 或调用 `start()` |

## 8. 快速自检

导入后读这几个值：

```gdscript
var n := sprite
print(n.position)        # 应等于 json 里的 position（父级为 2D 时减去父级 anchor）
print(n.offset)          # 应等于 -anchor（贴图与图层同尺寸时）
print(n.scale)           # 应等于 json 里的 scale
print(n.centered)        # false
```

对照表：

| 层 | position | offset |
|---|---|---|
| 左右护法（根级） | `(958.2, 750.0)` = json 原值 | `(-386.5, -86)` |
| 登入成功（父=空9，父锚点 0,180） | `(-14, -598)` = json `(-14,-418)` − `(0,180)` | `(-122, -55)` |
